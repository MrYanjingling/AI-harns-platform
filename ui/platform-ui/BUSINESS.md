## 1. 产品定位与术语

AI-harns-platform 是工业物联网平台，管理后台同时覆盖边缘网关服务与平台服务：前者负责 Modbus / OPC UA / S7 设备采集与反控，后者负责物模型、设备（Thing）接入、账号权限与审计。

| 术语 | 含义 |
|---|---|
| 网关（gateway） | 运行在边缘设备/边缘服务器上的采集服务，负责连接南向设备并上报数据 |
| 平台服务（platform） | 认证、用户/角色/组织、审计、物模型与设备（Thing）管理服务 |
| 数据服务（data） | 保存指标、KPI、测点与时序数据的服务（历史遗留） |
| 网关设备 | 通过 Modbus、OPC UA 或 S7 协议接入网关的工业设备 |
| 变量 | 网关设备上的一个可采集数据点，包含地址、类型、倍率、读写模式等 |
| 物模型（Thing Model） | 设备属性与特征的模板，`thingModelKey` 全局唯一 |
| 属性 | 物模型中的动态数据通道，设备按 `identifier` 上报属性值 |
| 特征 | 物模型中的静态描述定义，设备为其填写具体静态值 |
| 设备（Thing） | 基于物模型接入平台的设备，含 MQTT 与 HTTP 上报凭证 |
| TSL | 物模型的 JSON 导入/导出文档 |
| 在线 | `enable=1` 且最近 `online-ttl-seconds`（默认 60 秒）内有数据上报 |
| 审计日志 | 平台写操作（POST/PUT/PATCH/DELETE）的留痕，GET 不记录 |
| 测点（Tag） | 数据服务同步的 SCADA 测点，时序查询的最小对象 |
| 统计指标（Metrics） | 数据服务中的聚合指标定义，如总能耗、功率因数 |
| KPI | 由指标公式计算出的关键绩效指标，可设置目标值 |
| 时序 | 测点在时间轴上的历史数据点 |
| `r` / `rw` | 网关变量只读 / 可读可写；只有 `rw` 变量允许反控 |
| eTag | 网关设备版本号，用于乐观锁；更新与删除网关设备时必须回传 |

## 3. 通用交互规则

1. **加载 / 错误 / 空态**
   - 加载中不得只渲染 `null`：列表用骨架屏，整页用加载提示，区块用骨架/加载文案。
   - 请求失败统一展示可重试错误态，并透出后端错误信息。
   - 无数据与“筛选后无匹配”必须区分，前者引导创建，后者提供清除筛选。
2. **反馈**
   - 写操作成功/失败使用顶部 toast；表单内错误同时就近展示。
   - 危险操作（删除）必须二次确认。
3. **轮询**
   - 网关资源（CPU/内存/磁盘）：10 秒。
   - 设备列表：10 秒。
   - 设备详情：5 秒。
   - 指标、KPI、测点列表不轮询。
4. **时间与数字**
   - 展示时间：`yyyy-MM-dd HH:mm:ss`；简短展示 `yyyy-MM-dd HH:mm`；列表可显示相对时间。
   - 后端入参时间：`yyyy-MM-dd HH:mm:ss`；时序接口使用毫秒格式 `yyyy-MM-dd HH:mm:ss.SSS`。
   - 数字展示使用千分位；指标值最多 3 位小数，KPI/图表最多 2～3 位小数。
   - 百分比输入可能带 `%`，解析时去掉并夹在 `0..100`。
5. **主题**
   - 支持浅色/深色，选择持久化；首屏不得闪烁。
   - 图表与状态颜色必须在两种主题下可辨识。
6. **删除/编辑冲突**
   - 设备写入携带最近一次读取的 eTag。
   - 收到 412（版本冲突）或 404（已被删除）时，先失效设备缓存，让用户看到最新数据，禁止静默覆盖。
7. **未保存修改**
   - 表单展示“有未保存的修改”；取消/返回当前不做拦截。
   - 创建成功后进入设备详情；保存成功后返回设备详情。
8. **平台登录态**
   - 登录成功后 token 存于 `localStorage['harns-session-token']`，平台请求统一携带 `Authorization: Bearer <token>`。
   - 任意平台接口返回 401 时立即清除 token、清空查询缓存并跳转 `/login`；登录页成功后回到原地址。
   - 退出登录调用 `/auth/logout`（失败也清理本地会话）。
   - 工厂大屏 `/screen` 保持独立，不强制登录；其余管理页均需登录。
9. **平台分页**
   - 用户、角色、物模型、平台设备、审计日志均为服务端分页，使用 `page` / `pageSize`，每页可选 10/20/50/100，默认 10（审计默认 20）。
   - 搜索条件点击“查询”或回车后生效，并回到第 1 页；重置清空条件。
10. **敏感信息**
    - 设备密钥、MQTT 密码、HTTP Token 默认掩码展示，可切换显示并复制。
    - 审计日志中的请求/响应体由后端脱敏并按 16 KiB 截断，前端只展示。
11. **平台轮询**
    - 平台设备列表 10 秒、详情 5 秒；其余平台列表与详情不轮询。
12. **删除与批量操作**
    - 平台设备支持勾选当前页后批量删除，删除前二次确认并提示凭证立即失效。
    - 删除物模型会一并删除其属性；存在子组织时删除组织会被后端拒绝，前端展示后端错误。

## 4. 概览页

### 4.1 网关身份

展示 `GET /gatewayMeta` 返回：

| 字段 | 展示规则 |
|---|---|
| `name` | 网关名称 |
| `id` | 网关 ID，可复制 |
| `eTag` | 版本号（ETag），可复制 |
| `secret` | 默认脱敏；可切换显示、可复制；无值显示“未设置” |
| `modTime` | 最近更新，显示相对时间 |

网关状态徽标：

- 请求成功：`网关运行中`
- 请求失败：`网关不可用`
- 请求中：`连接中`

### 4.2 资源使用

- **CPU**：展示 `1min`、`5min`、`15min` 三个负载，百分比环形图。
- **内存**：展示 `Used / Total` 与使用率环形图。
- **磁盘**：按挂载点展示 `Used / Total`、使用率进度条。
- 颜色阈值：`< 75%` 成功、`75%～89%` 警告、`>= 90%` 危险。
- 资源数据每 10 秒刷新；单项失败只显示该项不可用，不影响其他区块。

### 4.3 设备统计口径

| 指标 | 口径 |
|---|---|
| 设备总数 | 列表全部设备 |
| 采集中 | `collecting` |
| 采集异常 | `collectingError + error` |
| 未运行 | `stopped + unconnected + emptyVariable` |
| 占比 | 对应数量 / 设备总数；总数为 0 时显示“暂无设备”或不展示百分比 |

### 4.4 状态分布

按固定顺序展示：`collecting`、`collectingError`、`unconnected`、`emptyVariable`、`stopped`、`error`。

- 分布条按数量占比绘制，仅渲染数量大于 0 的状态。
- 未知状态计入 `error` 口径。
- 每项展示数量与百分比。

### 4.5 最近更新设备

按 `modTime` 倒序取前 5 台，展示设备名、协议、状态、设备编码、更新时间。设备名为详情页链接。

## 5. 网关设备（Device）

### 5.1 设备摘要模型

列表与大部分跳转只依赖摘要字段：

| 字段 | 含义 |
|---|---|
| `id` | 设备 ID（32 位十六进制） |
| `name` | 设备名称 |
| `deviceCode` | 设备编码，建议使用资产编号 |
| `deviceType` | `modbus` / `opcUa` / `s7` |
| `deviceModel` | 协议下的具体型号 |
| `collectStatus` | 采集状态枚举 |
| `eTag` | 版本号，编辑/删除必须使用 |
| `modTime` | 最后修改时间 |
| `topic` | 可选，MQTT 上报主题；为空表示网关默认规则 |

### 5.2 协议与型号

| 协议 | 型号 | 说明 | 连接参数 |
|---|---|---|---|
| Modbus | `modbusTcp` | Modbus TCP，以太网 | `location` + `port`（默认 502） |
| Modbus | `modbusRtu` | Modbus RTU，串口 | `location` + 波特率/数据位/校验/停止位 |
| Modbus | `modbusRtuOverTcp` | RTU 经 TCP 透传 | `location` + `port` |
| OPC UA | `opcUa` | OPC UA 二进制协议 | `location`（`opc.tcp://host`）+ 端口（默认 4840）+ 可选用户名/密码 |
| S7 | `s71500` | 西门子 S7-1500 | `location` + 端口（默认 102）+ rack + slot |

协议在创建时选择；**创建后协议类型与型号均不可修改**。

### 5.3 设备状态

| 状态 | 文案 | 业务含义 | 是否视为运行中 |
|---|---|---|---|
| `collecting` | 采集中 | 连接正常，正在采集 | 是 |
| `collectingError` | 采集异常 | 可连接，但部分数据采集失败 | 是 |
| `unconnected` | 未连接 | 网关无法连接设备 | 否 |
| `emptyVariable` | 无变量 | 未配置任何采集变量 | 否 |
| `stopped` | 已停止 | 采集已停止 | 否 |
| `error` | 错误 | 设备运行发生错误 | 否 |
| 其他 | 未知 | 未识别的状态 | 否 |

“运行中”统一定义为 `collecting | collectingError`，用于决定可执行“重启/停止”还是“启动”。

### 5.4 设备列表

**展示列**：设备（名称 + ID）、协议/型号、状态、设备编码、最后更新、操作。

**筛选与搜索**

- 搜索：设备名称、设备编码、设备 ID，忽略大小写。
- 协议：全部 / Modbus / OPC UA / S7。
- 状态：全部 / 六种已知状态。
- 重置：一次清空搜索与两个筛选。
- 计数：展示筛选后数量；与总数不同时附加“总计 N”。

**行操作**

| 条件 | 操作 |
|---|---|
| 运行中 | 重启、停止 |
| 非运行中 | 启动 |
| 始终 | 删除、进入详情 |

- 状态操作调用 `PUT /devices/:id/{start|restart|stop}`，异步生效，操作后列表轮询刷新。
- 删除使用当前行 `eTag`，成功后 toast 并刷新列表。
- 删除确认文案需包含设备名，并说明“停止采集、不可撤销”。

**其他**

- 列表每 10 秒轮询；刷新时展示“正在刷新”提示。
- 空列表与筛选无结果分别提示。
- 页面底部提示启停为异步操作。

### 5.5 新建设备

**流程**

1. 选择协议（Modbus / OPC UA / S7）；可“更换协议”重选。
2. 填写基本信息、连接参数、采集变量。
3. 提交成功后跳转设备详情。

**创建后的初始状态**：设备以 `stopped` 创建，需要用户手动启动采集。

**默认值**

| 字段 | Modbus | OPC UA | S7 |
|---|---|---|---|
| `deviceModel` | `modbusTcp` | `opcUa` | `s71500` |
| `collectorCycle` | 1 秒 | 1 秒 | 1 秒 |
| `variableInterval` | 0 | 0 | 0 |
| 连接地址 | 空 | `opc.tcp://` | 空 |
| 端口 | 502 | 4840 | 102 |
| 串口参数 | 9600 / 8 / 无校验 / 1 | — | — |
| `slave` | 1 | — | — |
| `memoryLayout` | `ABCD` | — | — |
| `positionAddress` | 0 | — | — |
| rack / slot | — | — | 0 / 1 |
| 首个变量类型 | `int16` | `number` | `int16` |
| 首个变量地址 | `0` | 空 | 空 |
| `namespace` | — | 2 | — |
| `functionCode` | 3 | — | — |
| `rate` | 1 | — | 1 |
| `accessMode` | `r` | `r` | `r` |

默认值必须避开后端 `required` 的零值：采集周期至少 1 秒、`slave` 至少 1、功能码默认 3、OPC UA namespace 默认 2。

**校验规则**

| 字段 | 规则 |
|---|---|
| 设备名称 | 必填，1～64 字符；仅允许字母（含中文等 Unicode 字母）、数字、下划线、点、空格 |
| 设备编码 | 必填，1～32 字符；不能包含 `/` 或 `\` |
| 采集周期 | 整数，1～86400 秒 |
| 变量间隔 | 整数，0～86400 毫秒；0 表示不等待 |
| Topic | 可选，最多 256 字符；留空使用网关默认规则 |
| Modbus 地址 | TCP/RTU over TCP 必填 IP 或主机名；RTU 必填串口设备 |
| Modbus 端口 | 1～65535 |
| Modbus 串口 | 波特率限 1200/2400/4800/9600/19200/38400/57600/115200；数据位 5～8 |
| 从站地址 | 1～65535 |
| 内存布局 | `ABCD` / `BADC` / `CDAB` / `DCBA` |
| 起始地址偏移 | 0～65535 |
| OPC UA Endpoint | 必填，形如 `opc.tcp://host` |
| OPC UA 端口 | 1～65535 |
| S7 PLC 地址 | 必填 IP 或主机名 |
| S7 端口 | 1～65535 |
| S7 rack / slot | rack 0～7；slot 0～31 |
| 变量数量 | 至少 1 个 |

**提交映射**

- `variableInterval` 仅在大于 0 时上送，否则省略。
- `topic` 仅在去空格后非空时上送，否则省略。
- Modbus RTU 上送串口参数；其余 Modbus 型号上送 `port`。
- Modbus 变量地址转为整数；`bits` 仅 `bool` 类型上送，其余为 0。
- OPC UA 变量地址按字符串上送（如 `ns=2;s=Tag`），并携带 `namespace`。
- S7 变量地址按字符串上送（如 `DB1.DBW0`），并携带 `rate`。

### 5.6 编辑设备

- 进入时通过 `GET /devices/:id?exploded=true` 读取完整设备并转回表单。
- **协议类型与型号只读展示，不可切换**。
- 提交使用当前详情中的 `eTag` 作为 `If-Match`。
- 成功：toast + 返回详情。
- 412/404：失效设备缓存并提示用户重新加载，不自动覆盖。
- 页面顶部展示设备 ID、当前 eTag、最后修改时间。

### 5.7 设备详情

**操作区**

| 按钮 | 条件 | 行为 |
|---|---|---|
| 反控 | 存在至少一个 `rw` 变量 | 打开反控弹窗（全部可写变量） |
| 编辑 | 始终 | 进入编辑页 |
| 重启 / 停止 | 运行中 | 调用对应状态操作 |
| 启动 | 非运行中 | 调用启动 |
| 删除 | 始终 | 二次确认后删除并返回列表 |

**设备信息卡**

展示设备编码、协议/型号、采集周期（秒）、变量间隔（毫秒，0 显示“不等待”）、Topic（空显示“默认规则”）、变量数量、设备 ID、eTag、最后修改时间。ID 与 eTag 可复制。

**连接参数卡**

- Modbus：RTU 展示串口参数；非 RTU 展示端口；另展示从站地址、内存布局、起始偏移。
- OPC UA：Endpoint、端口、用户名（空显示“匿名”）、密码（有值掩码，无值“未设置”）。
- S7：PLC 地址、端口、Rack / Slot。

**采集变量表**

列：变量名、类型、地址、采集参数、当前值、读写、操作。

- 采集参数：Modbus 为 `FC{功能码}`、bool 追加 `bit {位}`、`×{倍率}`、`数量 {amount}`；OPC UA 为 `ns={namespace}`；S7 为 `×{rate}`。
- 当前值为空显示 `—`；布尔显示 `true/false`；对象转 JSON 字符串。
- `rw` 变量展示“下发”按钮，打开仅含该变量的反控弹窗；`r` 变量显示“只读”。
- 无变量时展示空态并引导编辑添加。

**刷新**：详情每 5 秒轮询；刷新时显示“同步中”。页面提示版本冲突时重新加载后再编辑。

### 5.8 变量模型

**通用规则**

- 变量名：必填，1～64 字符，不能包含 `/` 或 `\`；变量名作为测点/反控键，同一设备内应避免重名（当前表单未做重复校验）。
- 地址：必填；格式随协议变化。
- 读写模式：`r` 或 `rw`，默认 `r`。
- 默认值：表单模型保留 `defaultValue` 字段，但当前**未在界面开放，也不随创建/更新上送**；如需支持，必须先更新本文档。

**各协议变量字段**

| 协议 | 数据类型 | 专有字段 |
|---|---|---|
| Modbus | `bool`、`int16`、`uint16`、`int32`、`int64`、`float32`、`float64` | `address` 非负整数寄存器地址；`functionCode` 1～4；`bits` 0～7（仅 bool 可编辑）；`rate` -1,000,000～1,000,000（倍率）；`amount` 0～65535（寄存器数量） |
| OPC UA | `number`、`string` | `address` NodeID 字符串；`namespace` 必须 ≥ 1（默认 2）；`namespace = 0` 会被后端拒绝 |
| S7 | `bool`、`int16`、`uint16`、`int32`、`int64`、`float32`、`float64` | `address` S7 地址字符串（如 `DB1.DBW0`）；`rate` 倍率 |

**变量编辑器**

- 支持添加、行内编辑、复制、删除。
- 复制：在当前行后插入副本，名称追加“ 副本”。
- 删除：至少保留 1 个变量，最后一行不可删除。
- 数据类型下拉只展示当前协议允许的类型。
- Modbus 地址提示从 0 开始；bool 以外禁用“位”输入。

### 5.9 启停 / 重启

- 状态操作接口：`PUT /devices/:id/start`、`/restart`、`/stop`。
- 运行中（`collecting/collectingError`）可重启、停止；其余状态可启动。
- 操作异步，接口成功后以列表/详情轮询结果为准。
- 操作进行中禁用相关按钮，避免重复提交。

### 5.10 变量反控

**可写范围**：仅 `accessMode === 'rw'` 的变量。无 `rw` 变量时详情页不显示“反控”按钮。

**入口**

- 详情页“反控”：展示全部 `rw` 变量。
- 变量行“下发”：只展示该变量。

**值转换**

| 类型 | 规则 |
|---|---|
| `bool` | 接受 `true` / `1` 为真，`false` / `0` 为假；其他报错“布尔值只能是 true 或 false” |
| 数值类型（`int16`/`uint16`/`int32`/`int64`/`float32`/`float64`/`number`） | 必须为非空且可解析为数字；`NaN` 会被拒绝并提示“「…」不是有效数字” |
| `string` | 原样提交 |

- 弹窗打开时用变量当前值预填。
- 弹窗内逐变量输入；bool 使用下拉。
- 提交体为单键对象数组：`[{"变量名": 值}, ...]`，接口 `PUT /devices/:id/action`。
- 当前值为对象时按 JSON 字符串展示。
- 成功 toast 提示下发变量数量并关闭；失败在弹窗内展示错误。
- 写入结果取决于设备在线状态与寄存器可写性；界面只负责提交，不保证设备侧写入成功。

### 5.11 删除设备

- 入口：列表行删除、详情页删除。
- 必须二次确认，文案包含设备名并提示不可撤销。
- 携带当前 `eTag`；成功 toast；列表页留在列表，详情页返回列表。
- 412/404 按通用冲突规则处理。

### 5.12 设备域边界

- 协议/型号创建后不可变更；需要换协议只能新建。
- 设备至少一个变量；允许全部变量只读。
- 未知状态不得导致页面崩溃，按“未知/异常”处理。
- 任何设备写操作（创建除外）都不得绕过 eTag（状态启停/反控接口按后端契约不要求 If-Match）。

## 6. 数据服务

数据服务只提供查询，本前端不提供指标、KPI、测点的增删改。

### 6.1 统计指标

**列表**

- 数据源：`GET /metrics`，响应 `{ data, total }`。
- 展示：指标名称（缺失时用编码）、指标编码、计算方式（`calculateType`，可附 `metricsType`）、单位（`measureType`）、启用状态。
- 可单选/全选/取消全选；整行可点击切换。
- 首次加载默认选中前 4 个已启用且 `metricsCode` 非空的指标。

**查询**

- 条件：选中指标 + 开始/结束时间；粒度固定为小时 `h`。
- 时间范围默认最近 24 小时，支持 1 小时 / 24 小时 / 7 天快捷设置；开始必须早于结束。
- 请求：`POST /metricsData`，`{ metricsCodes, startTime, endTime, granularity: 'h' }`。
- 结果：每个指标一张卡片，展示名称、值（最多 3 位小数）、单位、起止时间。
- 未查询、加载中、查询失败、无数据分别展示对应状态。
- 结果底部展示查询区间与粒度。

### 6.2 KPI

**列表**

- 数据源：`GET /kpis`。
- 展示：名称、ID、公式（优先 `formula`，缺失用 `formulaOri`）、时间粒度、状态。
- 粒度文案：`h` 小时、`d` 天、`m` 月、`y` 年。
- 状态：`active` 显示“启用”；`draft` 显示“草稿”；其他原样显示。
- 首次加载默认选中所有 `status === 'active'` 的 KPI。
- 支持单选/全选/取消全选与整行点击。

**计算**

- 条件：选中 KPI + 时间范围；粒度固定小时。
- 请求：`POST /kpi`，`{ ids, startTime, endTime, granularity: 'h' }`。
- 结果：每个 KPI 一张卡片，展示名称、值（最多 2 位小数）、单位、起止时间。
- 目标对比：`targetData` 可解析为数字时，展示“目标值 + 单位”；`值 >= 目标` 为“达标”，否则“未达标”。不可解析时不展示目标行。
- 未计算、加载中、失败、无结果分别展示。

### 6.3 测点

- 数据源：`GET /tags`。
- 展示：测点名称（缺失用 `tagId`/`id`）、测点 ID、描述、类型/属性、SCADA、启用状态、最后同步时间。
- 启用判定：`enable === 1`；其余为停用。
- 筛选：搜索（`tagId`/`tagName`/`tagDesc`，忽略大小写）、SCADA、类型、启用状态。
- SCADA 与类型选项从当前数据去重生成。
- 展示筛选后数量与总数；展示启用/停用数量。
- “时序”按钮跳转 `/data/timeseries?select={tagId}`；停用测点也可跳转查询。
- 只读页面，不提供测点编辑。

### 6.4 时序查询

**查询条件**

| 条件 | 规则 |
|---|---|
| 数据源 | `fmcs`（FMCS）或 `escada`（Escada） |
| 测点 `select` | 英文逗号分隔；可直接粘贴，也可从测点列表勾选；建议最多 10 个 |
| 时间范围 | 开始必须早于结束；默认最近 24 小时；快捷 1 小时/24 小时/7 天 |
| 模式 | `raw` 原始值、`mean` 平均值、`usage` 差值（累计量桶内差值） |
| 条数上限 | 2～2000，默认 48 |

- 入口携带 `?select=` 时预填该测点，且不再自动选择默认测点。
- 无 `select` 参数时，首次加载优先选第一个已启用且有 `tagId` 的测点，否则选第一个测点。
- 查询按钮可用条件：至少一个测点、时间范围合法、条数上限 ≥ 2。
- 请求：`POST /{source}/tagTimeSeries`，字段 `{ select, start, end, limit, mode }`，时间使用毫秒格式（在公共时间后追加 `.000`）。

**结果展示**

- 多测点按时间戳合并为图表行；每个测点一条折线。
- 折线颜色来自固定色板，按顺序循环，保证明暗主题可辨识。
- X 轴显示 `HH:mm`；Tooltip 显示完整时间与数值；Legend 使用测点名（缺失用 `tagId`）。
- 页面显示曲线数量与时间点数量。
- 未查询、加载中、失败、无数据分别展示。

**测点概览表**

查询有结果时，按测点展示：名称/描述、ID、数据点数量、最小值、最大值、最新值。最新值取返回序列最后一个有效点。

### 6.5 时间范围通用规则

- 默认结束时间为当前时间，开始时间为 24 小时前。
- 开始时间必须严格早于结束时间，否则禁用查询并提示。
- 快捷范围以当前时间重新计算开始与结束。
- 指标/KPI 使用 `yyyy-MM-dd HH:mm:ss`；时序使用 `yyyy-MM-dd HH:mm:ss.SSS`。

## 7. 工厂大屏

### 7.1 入口与布局

- 入口：侧边栏“工厂大屏”，或概览页右上角“工厂大屏”按钮。
- 路由 `/screen` 位于管理后台外壳之外，不显示侧边栏；顶部提供“返回控制台”与全屏切换。
- 大屏固定使用深色视觉，不读取用户主题设置；浏览器标题为“工厂大屏 · AI-harns-platform”。
- 宽屏三栏：左侧设备态势（统计、协议分布、设备列表），中间 3D 场景，右侧选中设备实时数据；窄屏纵向排列。

### 7.2 数据来源

- 设备与变量：`GET /devices?exploded=true`，10 秒轮询；与管理后台设备列表共用查询缓存。
- 网关资源：`GET /gatewayCpu`、`GET /gatewayMem`，10 秒轮询；不可用时显示 `—`，不影响场景。
- 网关状态与名称：`GET /gatewayMeta`；顶部展示网关名称/连通状态与当前时间。
- 统计口径与概览页一致：采集中 = `collecting`；采集异常 = `collectingError + error`；未运行 = `unconnected + stopped + emptyVariable`；未知状态计入异常。
- “最后更新”取设备 `modTime`，按相对时间展示。

### 7.3 3D 场景

- 按协议划分 Modbus / OPC UA / S7 三个固定分区，颜色与协议徽标一致。
- 设备在分区内按名称排序后铺入网格（最多 4 列）；位置由协议与同协议内的排序决定，轮询刷新不会移动设备。
- 设备颜色按 `collectStatus` 着色；图例固定展示六种已知状态。`collecting` 与 `collectingError` 视为运行中，带呼吸发光效果。
- 交互：拖拽旋转、滚轮缩放、点击设备选中、点击空白取消选中；场景标签与左侧列表也可选中设备。
- 场景仅做可视化，不提供启停、反控等写操作；写操作仍在设备详情页完成。

### 7.4 选中设备

- 展示设备名称、状态、协议/型号、设备编码、连接地址、采集周期、变量数量、最后更新。
- 展示全部变量的当前值与类型：布尔显示 `true/false`，数值最多 2 位小数，空值显示 `—`；`rw` 变量标注“可读写”。
- 提供“查看设备详情”链接，跳转 `/devices/:id`。
- 设备被删除或刷新后不存在时，自动取消选中并回到未选中状态。

### 7.5 状态与降级

- 加载：场景区覆盖“正在接入设备…”。
- 错误：场景区展示可重试错误态，顶栏的网关状态与资源数据仍可用。
- 空态：无设备时展示“尚未接入设备”并引导新建设备。
- WebGL 不可用：场景区显示降级提示，页面其他区域仍可用。

## 9. 接口契约

### 9.1 服务与基址

- 网关服务、平台服务与数据服务默认都使用 `/api/v1`。
- `VITE_GATEWAY_BASE` / `VITE_PLATFORM_BASE` / `VITE_DATA_BASE` 可覆盖基址。
- 开发期由 Vite proxy 按路径分流：`/api/v1/auth` 与 `/api/v1/iot` → 平台服务（32300），网关与数据路径分别转发；生产环境由反向代理分流。
- 网关与数据服务使用 JSON；平台服务响应统一为 `{ code, message, data }`。
- 所有请求统一走 `request(service, path, options)`；错误统一抛 `ApiError`，界面展示 `errorMessage(error)`。

### 9.2 网关服务

| 方法 | 路径 | 用途 | 关键约定 |
|---|---|---|---|
| GET | `/gatewayMeta` | 网关身份 | 响应体含 `name/id/eTag/secret/modTime`；eTag 优先取响应体，其次响应头 |
| GET | `/gatewayCpu` | CPU 负载 | `{ cpus: { '1min','5min','15min' } }` |
| GET | `/gatewayMem` | 内存 | `{ mem: { Total, Used, UsedPercent } }`，字段首字母大写 |
| GET | `/gatewayDisk` | 磁盘 | `{ disk: { [mount]: { Total, Used, UsedPercent } } }` |
| GET | `/devices` | 设备列表 | `{ devices: DeviceSummary[] }`；`?exploded=true` 返回详情数组 |
| GET | `/devices/:id` | 设备详情 | `?exploded=true` 时返回完整设备 |
| POST | `/devices` | 创建设备 | v1 创建载荷；成功 201，返回详情 |
| PUT | `/devices/:id` | 更新设备 | 必须携带 `If-Match: {eTag}` |
| DELETE | `/devices/:id` | 删除设备 | 必须携带 `If-Match: {eTag}` |
| PUT | `/devices/:id/start` | 启动采集 | 异步 |
| PUT | `/devices/:id/restart` | 重启采集 | 异步 |
| PUT | `/devices/:id/stop` | 停止采集 | 异步 |
| PUT | `/devices/:id/action` | 变量反控 | 请求体 `Array<Record<string, unknown>>`，每项一个变量 |

### 9.3 数据服务

| 方法 | 路径 | 用途 | 请求/响应 |
|---|---|---|---|
| GET | `/metrics` | 指标列表 | `{ data: MetricsInfo[], total }` |
| GET | `/kpis` | KPI 列表 | `{ data: KpiInfo[], total }` |
| GET | `/tags` | 测点列表 | `{ data: TagInfo[], total }` |
| POST | `/metricsData` | 指标值 | `{ metricsCodes, startTime, endTime, granularity:'h' }` → `{ data: MetricsResult[], total }` |
| POST | `/kpi` | KPI 值 | `{ ids, startTime, endTime, granularity:'h' }` → `{ data: KpiResult[], total }` |
| POST | `/fmcs/tagTimeSeries` | FMCS 时序 | `{ select, start, end, limit, mode }` → `{ data: DataPointTimeSeries[], total }` |
| POST | `/escada/tagTimeSeries` | Escada 时序 | 同上 |

### 9.4 响应与错误

- 数据服务统一解包 `data`，列表缺失时按空数组处理。
- 网关设备列表解包 `devices`，缺失时按空数组处理。
- 错误响应可能是 `{ errors: [{ code, message }] }`、`{ code, message }` 或纯文本；前端统一提取可读消息。
- HTTP 语义：
  - `400`：参数/业务校验失败，展示后端消息。
  - `404`：资源不存在；设备域同时失效缓存。
  - `412`：eTag 冲突；失效缓存并提示刷新，禁止覆盖。
  - `428`：缺少 If-Match；视为前端缺陷并提示，不自动重试。
  - `5xx` / 网络失败：展示服务不可用/内部错误提示。
- 创建设备、更新设备、删除设备、启停成功后失效设备缓存（列表与详情）；反控成功后失效对应详情。

### 9.5 平台服务

平台接口统一返回 `{ code: 200, message: 'success', data }`；分页 `data` 为 `{ total, page, pageSize, list }`。除登录、验证码、公钥、设备认证/上报外均需 Bearer token。

**认证**

| 方法 | 路径 | 用途 | 关键约定 |
|---|---|---|---|
| POST | `/auth/login` | 登录 | `{ username, password, code?, key? }`；密码可用 RSA-OAEP(SHA-256) 加密，失败回退明文；返回 `{ token }` |
| POST | `/auth/logout` | 退出 | 删除服务端会话 |
| GET | `/auth/index` | 当前用户 | 返回 `CurrentUser`（含 `roleIds/orgIds`） |
| GET | `/auth/publicKey` | RSA 公钥 | Base64 X.509 DER；不可用时前端回退明文 |
| POST | `/auth/verificationCode` | 图形验证码 | 当前后端未启用校验，前端未使用 |

**用户 / 角色 / 组织**

| 方法 | 路径 | 用途 |
|---|---|---|
| GET/POST | `/iot/users` | 分页查询 / 创建用户（创建时可带 `roleIds/orgIds`） |
| GET/PUT/DELETE | `/iot/users/:id` | 详情 / 更新基础字段 / 删除 |
| PUT | `/iot/users/:id/password` | 重置密码为 `<userName>@qwer` 并使会话失效 |
| GET/POST | `/iot/roles` | 分页查询 / 创建角色 |
| GET/PUT/DELETE | `/iot/roles/:id` | 详情 / 更新 / 删除（同时清理用户绑定） |
| GET | `/iot/orgs/tree` | 组织树 |
| POST | `/iot/orgs` | 创建组织（`parentId` 为空或 `0` 表示根） |
| GET/PUT/DELETE | `/iot/orgs/:id` | 详情 / 更新 / 删除（存在子组织时拒绝） |

**审计日志**

| 方法 | 路径 | 用途 | 关键约定 |
|---|---|---|---|
| GET | `/iot/auditLogs` | 分页查询 | `page/pageSize/app/userId/path/method/resultCode/start/end`；时间格式 `yyyy-MM-dd HH:mm:ss` |

**物模型**

| 方法 | 路径 | 用途 |
|---|---|---|
| GET/POST | `/iot/thingModels` | 分页查询 / 创建（可带初始属性、特征） |
| GET/PUT/DELETE | `/iot/thingModels/:id` | 详情 / 更新名称描述 / 删除（属性一并删除） |
| POST | `/iot/thingModels/:id/properties` | 批量追加属性（批量原子） |
| PUT | `/iot/thingModels/:id/properties/:identifier` | 更新单个属性；路径标识符为准 |
| DELETE | `/iot/thingModels/:id/properties` | body 为标识符数组，幂等删除并返回 `{ deleted }` |
| GET/PUT | `/iot/thingModels/:id/tsl` | 导出 / 导入 TSL |

**设备（Thing）**

| 方法 | 路径 | 用途 |
|---|---|---|
| GET/POST | `/iot/things` | 分页查询 / 批量创建（1~100 台） |
| DELETE | `/iot/things` | body 为 id 数组；返回 `{ deleted }` |
| GET/PUT | `/iot/things/:id` | 详情（含凭证/特征/图片） / 更新可变字段 |

**文件**

| 方法 | 路径 | 用途 | 关键约定 |
|---|---|---|---|
| POST | `/iot/files` | 上传图片 | `multipart/form-data` 单字段 `file`；JPEG/PNG/WebP/GIF，≤10 MiB；返回 `{ key }` |

### 9.6 平台响应与错误

- 成功统一解包 `data`；删除类接口 `data` 可能为 `null`。
- 业务错误 HTTP 400，`code` 从 10001 起；401 仅表示未登录/会话过期；403 无权限；500 内部错误。
- 校验错误包含 `errors[].field`（如 `properties[0].identifier`），前端优先展示 `errors[].message`。
- 401 触发全局会话清理与登录页跳转；其余错误展示后端本地化消息，不做自动重试。
- 平台写入成功后按资源失效缓存：物模型 → 物模型列表/详情；设备 → 设备列表/详情；身份与组织 → 对应列表与树。

## 10. Mock 业务规则

- 仅在 `VITE_USE_MOCK=true` 时启用；此时不注册 Vite proxy。
- Mock 为内存态，刷新页面重置；响应形状必须与 Go 服务一致。
- 创建：分配 32 位十六进制 ID，`eTag='1'`，状态 `stopped`。
- 更新/删除：校验 `If-Match`；缺失返回 428，不匹配返回 412；更新后 eTag 递增。
- 启动/重启：状态变为 `collecting`；停止：变为 `stopped`；更新 `modTime`。
- 反控：变量必须存在且为 `rw`，否则 400；成功返回 202。
- 未实现的 `/api/v1/*` 显式返回 404，避免误判为真实后端。
- 列表返回摘要字段；`exploded=true` 返回完整设备。
- 数据服务返回种子指标、KPI、测点，以及按查询参数生成的确定性时序数据。
- 平台 mock 同样有状态：登录建立内存会话（`admin / harns@iot`，其他种子用户为 `<userName>@qwer`），退出或重置密码使会话失效；`/auth/publicKey` 返回空串以走明文登录。
- 平台种子包含 3 个物模型、6 台设备、3 个用户、3 个角色、5 个组织与 6 条审计日志；创建/更新/删除均同步内存数据并递增 `version`。
- 平台设备凭证按 Go 规则生成：`dk_` + 16 位小写字母数字的 `deviceKey`、64 位 hex 的 secret/token、`iot/<deviceKey>/up|down` Topic；在线状态按 `enable=1` 且 60 秒内有上报计算。
- 物模型名称/Key、设备名/Key、MQTT clientId/username、用户名、角色名/编码的唯一性与错误码需与后端保持一致；组织存在子组织时删除返回 400。
- 上传接口只校验 `multipart/form-data` 与文件非空，返回 `images/YYYY/MM/mock-<id>.<ext>`，不真正存储文件。
- 新增/修改接口时，必须同步实现 mock 路由与 fixtures。

## 11. 关键业务不变量

1. 设备必须属于且仅属于一种协议；创建后不可更换协议/型号。
2. 设备至少配置一个变量；变量名作为反控键，应避免在同一设备内重名。
3. 只有 `rw` 变量可以反控；只读变量不得出现下发入口。
4. 运行中严格定义为 `collecting | collectingError`。
5. 设备更新与删除必须携带最新 eTag；冲突时让用户看到最新版本，禁止静默覆盖。
6. 新建设备初始为停止状态，由用户显式启动。
7. 创建/更新时不发送空的可选字段（`topic`、`variableInterval`、OPC UA 用户名/密码）。
8. 时间范围必须 `start < end`；指标/KPI 当前只支持小时粒度。
9. 数据服务在本前端只读，不提供增删改入口。
10. 状态、协议、数据类型、标签文案、颜色与阈值集中维护，禁止在页面中重复硬编码。
11. 业务变更必须先更新本文档，再更新代码与 mock；文档与实现必须始终一致。
12. 平台管理请求必须携带 Bearer token；401 必须立即清理会话并回到登录页，禁止继续展示受保护数据。
13. 物模型 `thingModelKey`、属性 `identifier` 创建后不可修改；同模型内标识符与名称唯一。
14. Thing 的 `deviceKey`、`deviceSecret`、`token`、上下行 Topic 创建后不可修改。
15. Thing 在线 = `enable=1` 且最近 60 秒内有上报；`enable=0` 强制离线。
16. 角色/组织绑定只在创建用户时提交；编辑用户不发送 `roleIds/orgIds`。
17. 审计日志只记录写操作且只读；请求/响应体已由后端脱敏与截断，前端不得二次存储或回传。
18. 物模型导入会整体替换属性，导入前必须提示备份；导入失败不得改动本地缓存数据。

## 12. 登录与平台会话

- `/login` 是 `AppShell` 之外的全屏页；已持有 token 时直接回到 `/`。
- 表单字段：用户名（必填，≤64）、密码（必填，≤512）。提交时先请求 `/auth/publicKey`，可用则用 RSA-OAEP(SHA-256) 加密密码，失败或公钥不可用回退明文。
- 登录成功：保存 token、拉取 `/auth/index`，跳转到来源地址（来自路由 state 的 `from`），无来源则回 `/`。
- 登录失败：展示后端消息（用户名/密码错误、账号禁用、账号锁定）；连续失败 5 次锁定 60 分钟，锁定信息由后端返回。
- 初始化管理员为 `admin / harns@iot`；Mock 模式在登录页给出提示。
- 会话过期：任何平台接口 401 → 清理 token 与查询缓存 → 跳转 `/login`。
- AppShell 顶栏展示当前用户昵称/工号与退出按钮；退出无论接口成败都清理本地会话。
- `/screen` 工厂大屏不要求登录；其余管理页由 `RequireAuth` 保护。

## 13. 物模型

### 13.1 列表

- 服务端分页 + 关键词搜索（名称 / Key），默认每页 10 条。
- 表格展示名称、Key、描述、属性数、更新时间；点击行进入详情，行尾可删除（二次确认，属性一并删除）。
- 空态区分“无物模型”和“搜索无匹配”。

### 13.2 新建与编辑

- 名称必填、≤64、全局唯一；`thingModelKey` 可选，留空由后端生成，格式 `^[a-zA-Z][a-zA-Z0-9_-]{3,63}$`，创建后不可修改。
- 描述 ≤255。新建成功后进入详情页继续添加属性。
- 详情页可修改名称与描述，Key 只读。

### 13.3 属性

- 字段：标识符（必填，`^[A-Za-z][A-Za-z0-9_]*$`，≤64，不能为 `time`、`device_id`，模型内唯一，创建后不可修改）、名称（必填，字母开头，≤64，模型内唯一）、数据类型、读写标记 `r/w/rw`、是否必填、描述（≤255）、排序（非负整数）。
- 数据类型：
  - `int / long / float / double`：可选单位、单位名、最小值、最大值（可解析时 min ≤ max）。
  - `bool`：可选真值/假值文案。
  - `enum`：取值列表非空、取值整数且不重复。
  - `text`：长度必填且为正整数。
  - `array`：元素类型必填；元素个数可选，1~512。
  - `struct`：字段非空，字段标识符唯一，可递归定义类型（前端最多嵌套 2 层）。
- 新增属性走批量接口（单条）；编辑时标识符只读，提交路径与 body 标识符一致。
- 删除属性二次确认，按标识符幂等删除。
- 字段校验错误按后端字段路径展示；提交失败展示后端 `errors[].message`。

### 13.4 特征

- 特征是静态定义，无 `rwFlag/required`；只在创建物模型或导入 TSL 时维护。
- 详情页“特征”页只读展示标识符、名称、数据类型、描述与排序，并提示通过 TSL 维护。
- 设备的特征值在平台设备详情维护。

### 13.5 TSL 导入导出

- 导出：`GET /iot/thingModels/:id/tsl`，浏览器下载 `<thingModelKey>.json`。
- 导入：`PUT /iot/thingModels/:id/tsl`，仅接受 JSON，文档必须包含 `properties` 数组；`[]` 表示清空属性。
- `thingModelKey` 可省略，提供时必须与当前 Key 一致；`name/description` 提供时更新；`features` 省略时保留，提供时整体替换。
- 导入前建议先导出备份；导入成功后失效物模型列表/详情缓存。
- 导入内容语法错误、缺少 `properties` 或语义校验失败时，展示后端错误且不修改本地数据。

## 14. 平台设备（Thing）

### 14.1 列表

- 服务端分页 + 关键词搜索（设备名称 / Device Key），默认每页 10 条；列表 10 秒轮询。
- 表格：设备（名称 + Key）、物模型、启用状态、在线状态、最后上报（相对时间）、上行 Topic、操作。
- 在线定义：`enable=1` 且最近 60 秒内有上报；禁用设备强制离线。
- 支持勾选当前页批量删除；删除前二次确认，提示凭证立即失效。
- 列表不返回密钥、Token、MQTT 密码、特征值与图片。

### 14.2 批量创建

- 必须先选择物模型；一次 1~100 台，全部成功或全部回滚。
- 每行：设备名称（必填、≤64、同模型内唯一）、Device Key（可选，格式 `^[a-zA-Z][a-zA-Z0-9_-]{3,63}$`，全局唯一；留空生成 `dk_` 前缀）、描述（≤255）。
- 可选择填写特征值：只允许物模型中已定义的特征标识符；复杂类型（array/struct）用 JSON 输入。
- 图片不在批量创建时上传，创建后在设备详情维护。
- 创建成功后展示凭证结果页：设备名称/Key、MQTT clientId/username/password、HTTP Token、Device Secret、上下行 Topic，并支持逐项复制；可继续创建或进入列表。

### 14.3 详情与凭证

- 详情 5 秒轮询；展示启用/在线状态、最后上报、所属物模型、Device Key、上下行 Topic、创建/更新时间。
- 接入凭证：MQTT Client ID、MQTT Username、MQTT Password、Device Secret、HTTP Token；敏感字段默认掩码，可切换显示并复制。
- `deviceKey`、`deviceSecret`、`token`、`upTopic`、`downTopic` 创建后不可修改。
- 启用开关即时生效（`enable` 0/1）；禁用后在线状态强制为离线。

### 14.4 特征值与图片

- 特征值表格按物模型特征定义展示当前值；未定义但设备上存在的特征键标记为“未定义特征”。
- 编辑特征值时只提交有值的特征（清空即移除），保存时整体替换 `features`。
- 图片上传：JPEG/PNG/WebP/GIF，≤10 MiB；返回的 MinIO key 必须以 `images/` 开头。配置 `VITE_MINIO_PUBLIC_BASE` 时按 `<base>/<key>` 预览，否则只展示对象 Key；可移除图片（提交空串）。

### 14.5 编辑与删除

- 可编辑：设备名称（同模型内唯一）、描述、MQTT clientId/username/password。
- 删除单台或批量删除后返回列表；不存在的 id 忽略，响应返回实际删除数量。

## 15. 用户、角色与组织

### 15.1 用户

- 列表服务端分页 + 关键词（用户名 / 工号 / 昵称）；展示昵称+用户名、工号、角色、状态、最后登录。
- 新建：用户名、工号、昵称必填；密码可选（≥6，≤64），留空使用默认密码 `<userName>@qwer`；可选出生日期、性别、邮箱、手机、备注、认证方式、认证密钥、有效时长、状态，以及角色/组织绑定。
- 角色与组织绑定只在创建时提交；后端更新接口不接受 `roleIds/orgIds`，编辑弹窗只读展示现有绑定。
- 编辑：可改用户名、工号、昵称、出生日期、性别、邮箱、手机、备注、认证方式、认证密钥、有效时长、状态与密码（留空不改）。
- 重置密码：二次确认，后端重置为 `<userName>@qwer` 并使该用户会话失效。
- 删除：二次确认；角色/组织绑定一并清理，不可恢复。

### 15.2 角色

- 列表分页 + 关键词（名称 / 编码）；展示名称、编码、描述、状态、更新时间；`admin` 编码标记为内置超管。
- 新建/编辑：名称、编码必填且 ≤64，描述 ≤255，状态启用/禁用。
- 删除角色会清理用户绑定，二次确认。

### 15.3 组织

- 组织为树状结构，无分页；展示层级、编码、排序、状态、描述。
- 新建根组织或某节点的下级组织；上级可为空（根），`parentId` 为 `0` 按根处理。
- 编辑时可调整上级，但不能选择自身及其子树。
- 删除：存在子组织时后端拒绝并展示错误；删除会清理用户组织绑定。
- 用户创建弹窗中的组织多选使用同一棵树并按层级缩进。

## 16. 审计日志

- 只记录写操作（POST/PUT/PATCH/DELETE），GET 不记录。
- 筛选：应用（IOT/EMS/EAM）、请求方法、结果码、用户 ID、路径（模糊）、开始/结束时间（`yyyy-MM-dd HH:mm:ss`）。
- 列表分页，默认每页 20 条；展示时间、用户、操作类型与描述、方法+路径、HTTP 状态、耗时、IP。
- 点击行打开详情：应用、操作、用户、时间、状态/业务码、耗时、IP、Trace ID、User-Agent、Query、请求体、响应体、错误信息。
- 请求/响应体由后端脱敏并按 16 KiB 截断；前端只读展示并支持复制。
