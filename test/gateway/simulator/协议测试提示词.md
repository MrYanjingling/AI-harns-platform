# 网关协议模拟器测试提示词

## 可直接复制的提示词

```text
请测试 <协议名称>。

网关驱动列表见下方“待测试驱动列表”，只执行已勾选的驱动，未勾选的跳过。

先阅读仓库根目录 AGENTS.md、test/gateway/simulator/PlcSimulator协议启动命令表.md 和本文件，再按下面的流程执行：

1. 从启动命令表确认模拟器启动命令并启动对应模拟器。
2. 如果是串口协议，从模拟器日志中找到 external 后面的串口，采集实例连接该串口。
3. 创建采集实例，默认 1000 个点位，必须包含 BOOL、INT16、INT32、FLOAT32、FLOAT64 五种类型。
4. 如果协议支持多个区域，尽量分布到多个区域，地址不能重叠。
5. 等待采集进入 collecting，确认 1000 个点位都有值。
6. 对全部点位执行反控：
   - BOOL：地址编号为单数写 true，双数为 false。
   - INT16 / INT32：写入地址编号。
   - FLOAT32 / FLOAT64：写入“地址编号 + 0.1”。
7. 反控后停止再启动采集实例，清除本地缓存，再回读 1000 个点位并逐点比对。
8. 验证完成后，按本次要求停止或保留采集实例和模拟器。
9. 如果出现问题，排查原因并把报告写到 test/gateway/report/。
10. 测试期间不允许修改代码；确认确实是代码问题并得到明确同意后，才能修改。
11. 测试报告不提交到 Git，除非用户明确要求。

本次测试的额外要求：
- 采集实例：<删除 / 保留>
- 模拟器：<停止 / 保持运行>
- 其他：<无 / 补充说明>
```

## 执行细则

### 1. 准备

- 阅读 `AGENTS.md`，遵守仓库规范。
- 从 `test/gateway/simulator/PlcSimulator协议启动命令表.md` 查找协议标识、默认端口和启动命令。
- 没有启动命令时先询问用户，不要猜。
- 记录模拟器版本、启动命令、端口或串口、驱动类型、协议配置。

### 2. 启动模拟器

- 使用终端启动模拟器，日志重定向到临时文件，例如 `/tmp/plcsim-<protocol>.log`。
- TCP 协议等待端口可连接。
- 串口协议从日志中查找：

```text
external=/dev/ttysXXX
```

- 采集实例必须连接 `external` 串口，不是 `internal`。

### 3. 采集实例

- 默认 1000 点。
- 五种类型各 200 点：

```text
BOOL 200
INT16 200
INT32 200
FLOAT32 200
FLOAT64 200
```

- 点位名称必须唯一，符合变量名规则。
- 地址不能重叠，多字节类型要按字或字节宽度留出空间。
- 如果协议有多个可写区域，尽量分散到至少两个区域。
- 创建后轮询采集状态，目标状态：

```text
collecting
```

- 如果状态是 `collectingError`，记录 `lastError`，不要直接判定为“测试完成”。

### 4. 反控规则

地址编号取协议地址中的数字部分，例如：

```text
D100       -> 100
W20        -> 20
CIO0004    -> 4
DB1.DBW0   -> 0
```

规则：

- BOOL：
  - 地址编号为单数 -> `true`
  - 地址编号为双数 -> `false`
- INT16 / INT32：
  - 写入地址编号本身
- FLOAT32 / FLOAT64：
  - 写入 `地址编号 + 0.1`
  - 例如地址 1 -> `1.1`，地址 2 -> `2.1`
- 如果协议地址本身包含多个区域或站号，使用实际点位的数字地址作为编号。
- 如用户对某协议另有反控规则，以用户说明为准。

### 5. 验证

反控提交后不能只看接口返回 `accepted`，必须回读：

1. 等待至少一个采集周期。
2. 停止采集实例。
3. 重新启动采集实例。
4. 等待重新进入 `collecting`。
5. 再读取全部 1000 个点位。
6. 逐点比较：
   - BOOL：精确比较
   - INT16 / INT32：整数比较
   - FLOAT32：允许合理浮点误差，例如 `1e-3`
   - FLOAT64：允许更小误差，例如 `1e-6`
7. 统计：

```text
listed
nulls
matched
mismatches
missing
```

8. 输出前若干个 mismatch 的变量名、地址、期望值、实际值。

### 6. 清理

按本次用户要求执行：

- 默认：停止采集实例、停止模拟器。
- 用户要求保留数据：保持采集实例运行、保持模拟器运行。
- 用户要求删除：停止后删除测试采集实例。
- 如果授权变量不足：先删除之前已测试的采集实例，再创建本次实例。
- 不要删除用户未同意删除的实例。

### 7. 报告

发现问题时写入：

```text
test/gateway/report/<协议>-1000-report.md
```

报告至少包含：

- 时间
- 模拟器启动命令
- 端口或串口
- 驱动类型与协议配置
- 采集实例名称和 ID
- 点位设计和区域分布
- 初始采集结果
- 反控 accepted 数
- stop/start 后回读结果
- mismatch / null / missing 统计
- 模拟器日志关键错误
- 根因判断
- 是否修改代码、等待谁确认
- 当前实例和模拟器状态

报告不提交 Git，除非用户明确要求。

### 8. 已知协议注意点

- **S7**：单帧 item 数通常最多 20，PDU 大小不等于 item 数上限。
- **Modbus / HostLink 串口**：必须使用模拟器打印的 `external` 端口。
- **HostLink C-Mode**：TS 是位状态区，BOOL 写入可能不受支持；不要假设 `WG` 可用。
- **Omron CIP**：模拟器未注册标签时会用 2000 槽哈希地址，1000 个标签会冲突；需要 `--points-file` 显式注册标签，或使用真实 PLC。
- **CIP 响应**：标准响应可能带 element count，部分模拟器不带 count；驱动/解析需要兼容两种格式。

### 9. 硬性约束

- 测试期间不修改代码。
- 任何代码修改必须先确认是代码问题，并得到用户明确同意。
- 不提交测试报告。
- 不把模拟器限制误判为驱动缺陷，报告里要写清证据。
- 不静默跳过失败点位；失败必须记录变量、地址、期望值和实际值。
